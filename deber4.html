Deber 4: CRUD Local con Room

Implementación de persistencia de datos en Android usando SQLite

Paso 1: Definir la Tabla (Entity)

Lo primero que hice fue crear la estructura de mi tabla. En Room, esto se hace con una clase simple donde defino qué columnas quiero (como el ID, título y descripción).

@Entity(tableName = "notas")
data class Note(
  @PrimaryKey(autoGenerate = true) val id: Int = 0,
  val title: String,
  val description: String
)
¿Qué aprendí? Que el autoGenerate = true es clave para que Room cree los IDs solito, igual que hacía el push() de Firebase.

Paso 2: Crear el DAO (La interfáz)

El DAO es donde escribí las "órdenes" que la base de datos debe obedecer. Aquí definí mis métodos para insertar, leer, actualizar y borrar.

@Dao
interface NoteDao {

  @Insert suspend fun insertNote(note: Note)

  @Query("SELECT * FROM notas")
  fun getAllNotes(): Flow<List<Note>>

  @Update suspend fun updateNote(note: Note)

  @Delete suspend fun deleteNote(note: Note)
}

Paso 3: Conectar con la UI (ViewModel)

Como vimos en mi captura de pantalla anterior, el ViewModel es el que da las órdenes. Usé insertNote() para conectar mi botón de la pantalla con el DAO.

fun insertNote() {
  viewModelScope.launch(Dispatchers.IO) {
    repository.insertNote(miNotaObjeto)
  }
}
Dato importante: Usé viewModelScope.launch porque las operaciones de base de datos no pueden trabar la pantalla; deben ir por "un carril rápido" aparte.

Paso 4: Mis operaciones CRUD completas

Así es como funcionan mis acciones en la app:

  • Create: Al llamar a insertNote(), Room crea una fila nueva en el almacenamiento del celular.
  • Read: Uso un Flow para que, si cambio una nota, la lista se actualice sola en la pantalla.
  • Update: Al editar, Room busca la nota por su ID y sobrescribe los valores antiguos.
  • Delete: Simplemente selecciono la nota y Room la elimina de la memoria interna.
