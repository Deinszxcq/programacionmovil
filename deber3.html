Deber 3: CRUD en Tiempo Real

Guía explicativa sobre el manejo de datos con Firebase Realtime Database

Conceptos Clave

Antes de programar, entendí que esta base de datos no usa tablas, sino un árbol de objetos JSON. Todo se organiza por "Rutas".

La Referencia (ref): Es como el GPS. Le dice a Firebase en qué parte del árbol queremos trabajar. Por ejemplo, ref(db, 'usuarios') apunta a la carpeta principal de usuarios.

Paso 1: Crear datos (CREATE)

Para añadir información sin borrar lo que ya existe, usé push(). Esto es importante porque genera una "llave" única para cada registro.

// 1. Localizo la carpeta
const listaRef = ref(db, 'usuarios');

// 2. Genero un espacio nuevo con ID único
const nuevoUsuarioRef = push(listaRef);

// 3. Guardo los datos en ese espacio
set(nuevoUsuarioRef, { nombre: "Juan", edad: 22 });
¿Por qué push? Si usara solo set() en la ruta 'usuarios', cada vez que alguien guardara algo, borraría al usuario anterior. push() crea un ID aleatorio como -NXjK8... para que todos convivan.

Paso 2: Leer datos (READ)

Aquí usé onValue(). Lo genial de esta función es que mantiene la conexión abierta: si los datos cambian en la nube, mi app se entera al instante.

onValue(ref(db, 'usuarios'), (snapshot) => {
  const datos = snapshot.val();
  console.log("Datos actuales:", datos);
});
Snapshot: Es como una "foto" de los datos en ese preciso momento. Con snapshot.val() convertimos esa foto en un objeto que JavaScript puede leer.

Paso 3: Actualizar (UPDATE)

Para editar, aprendí que es mejor usar update() que set(). La diferencia es que update solo cambia los campos que le pides y mantiene el resto intacto.

// Solo cambio la edad, el nombre se queda igual
const rutaEdicion = ref(db, 'usuarios/' + idUsuario);
update(rutaEdicion, { edad: 25 });

Paso 4: Eliminar (DELETE)

Eliminar es lo más sencillo, solo necesito la ruta exacta del ID que quiero borrar.

// Borro al usuario por su ID
remove(ref(db, 'usuarios/' + idUsuario));
